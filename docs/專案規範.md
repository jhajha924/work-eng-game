> 給開發者與 AI 審查（GitHub 上的自動程式碼審查）共同遵守的規則。審查 Pull Request 或 commit 時，請以本文件為準。
> 有新規則時直接補在對應章節，並在最下方「變更紀錄」記一筆。

## 2. Git

### 2.1 身分

- commit 的作者與提交者**只能是** `jhajha924 <47804331+jhajha924@users.noreply.github.com>`。
- 身分設定在專案層 `.git/config`，**不使用全域設定**。
- 遠端網址固定為 `https://jhajha924@github.com/jhajha924/work-eng-game.git`。
- 推送前檢查：`git log --format="%an <%ae>"` 只能出現上述身分。

### 2.2 commit 訊息

格式：`類型: 說明`

| 類型 | 用途 |
|---|---|
| `feat` | 新功能 |
| `fix` | 修正錯誤 |
| `chore` | 設定、建置、套件等雜務 |
| `docs` | 只改文件 |
| `test` | 只改測試 |
| `refactor` | 重構（不改變行為） |
| `ci` | GitHub Actions 等自動化流程 |

- 一個 commit 只做一件事；`git add` 盡量指定檔名，不要一次全加。

### 2.3 不可進入版本庫的東西

- 機密：API 金鑰、密碼、權杖、`.dev.vars*`、`.env*`（已列在 `.gitignore`）。
- 機密只放在 Cloudflare Worker 的 secret（`npx wrangler secret put`）或 GitHub 版本庫的 Secrets。
- 個人與工作相關資訊（真實 email、工作帳號、公司名稱）。

## 3. Cloudflare

| 規則 | 說明 |
|---|---|
| **改了 `wrangler.jsonc` 後，必須執行 `npm run cf-typegen`，並把更新後的 `worker-configuration.d.ts` 一起 commit** | 型別檔由設定產生；不同步時程式裡的 `env.XXX` 會出現型別錯誤或缺漏 |
| `worker-configuration.d.ts` 不可手動修改 | 一律由 `npm run cf-typegen` 產生；ESLint 也不檢查此檔 |
| 資源名稱一律用 `work-eng-game` | Worker、D1 都用這個名稱，不可和同帳號的其他專案共用資源 |
| D1 綁定名稱是 `DB` | 程式中以 `env.DB` 存取 |
| `/api/*` 由 Worker 優先處理 | `wrangler.jsonc` 的 `assets.run_worker_first` 已設定；新增 API 一律放在 `/api/` 底下 |
| 本機開發使用本機模擬資料庫 | 不連線上 D1，避免動到正式資料 |

## 4. 程式碼

- TypeScript 嚴格模式，不使用 `any`（真的需要時加註解說明原因）。
- 核心邏輯（計畫引擎、單字卡排程、經驗值與徽章判斷、同步合併）寫成**純函式**並附單元測試。
- 動畫需尊重系統的「減少動態效果」設定，時間 150～400 毫秒。
- 手機優先：最小寬度 360px 必須能完整操作。

## 5. 品質關卡

每次 push，GitHub Actions 依序執行，任何一步失敗都**不會部署**：

1. `npm ci`：依 `package-lock.json` 安裝套件
2. `npm run lint`：ESLint 檢查
3. `npm run build`：TypeScript 型別檢查＋打包
4. （之後加入）`npm test`：單元測試
5. 只有 `main` 分支：`npx wrangler deploy`

## 6. 開發環境注意事項（Windows）

- 終端機是 Windows PowerShell 5.1：**不支援 `&&`**，多個指令要分行執行。
- 換行符號：版本庫內一律 LF，Windows 工作目錄由 git 自動轉 CRLF，`LF will be replaced by CRLF` 警告可忽略。
