# 單字卡與 FSRS

## 這段在做什麼（三句話以內）

把內容包裡的單字與句型變成單字卡，用 FSRS 演算法算出每張卡下次什麼時候該複習。
每天打開單字卡頁，就照「先到期的複習卡、再補最多 15 張新卡」的順序練「看中文 → 說出英文」。
評分後的卡片狀態存在本機，登入後和打勾紀錄一樣同步到另一台裝置。

## 關鍵觀念

| 觀念 | 白話說明 | 在哪裡 |
|---|---|---|
| **間隔重複** | 快忘記的時候再複習一次最有效；記得越牢，下次間隔拉得越長 | 整個 `src/cards/` |
| **FSRS** | Anki 新版用的排程演算法。每張卡記兩個數字：**穩定度**（記憶能維持多久）與**難度**（這張卡對你多難），評分後更新這兩個數字，算出下次到期日 | `src/cards/fsrs.ts`（包一層 ts-fsrs） |
| **四種評分** | 重來（忘了）、困難、良好、簡單；評得越好，下次間隔越長 | `src/cards/types.ts` 的 `Rating` |
| **學習階段** | 新卡第一次評分後先進「學習中」，幾分鐘後再考一次；答對才進入以天計算的「複習」 | `src/cards/queue.ts` 的提前學習 |
| **主動回想** | 正面只看中文，自己先想英文再翻面，比只看英文更能記住 | `src/cards/CardsPage.tsx` |
| **穩定的卡片 id** | id 由內容包、種類與英文轉成的代號組成（例如 `demo:v:follow-up`），每台裝置算出來都一樣，同步才對得上 | `src/cards/deck.ts` 的 `cardSlug` |
| **純函式佇列** | 「今天要考哪些卡」只看牌組、卡片狀態與現在時間，不碰資料庫，所以能用一般單元測試涵蓋所有情境 | `buildQueue` |
| **同一套同步流程** | 打勾紀錄與卡片狀態共用「送出未同步 → 伺服器較新者為準 → 用 rev 游標取回」的流程，只是 API 路徑與游標不同 | `src/sync/syncClient.ts` 的 `syncCollection` |

### 範例：一張新卡的一天

1. 9:00 第一次看到「議程」，想到 agenda，翻面確認後按「良好」→ 進入學習中，10 分鐘後到期。
2. 因為 20 分鐘內就到期，它留在今天的佇列裡，等等再出現一次。
3. 9:12 再看到時按「良好」→ 進入複習階段，下次到期是幾天後；今天的新卡額度用掉 1 張。
4. 30 秒後（或切到背景時）同步，另一台裝置同步後這張卡的到期日相同。

## 為什麼這樣設計，放棄了什麼

| 決定 | 放棄的做法 | 理由 |
|---|---|---|
| 用 ts-fsrs，版本固定 5.4.2 | 自己寫 SM-2；用最新的 6.0.0 | FSRS 比 SM-2 準；6.0.0 剛發布且要求 Node 24 以上，5.4.2 已穩定數個月 |
| 關閉隨機擾動（fuzz） | 預設的隨機擾動 | 相同輸入一定得到相同結果，測試與兩台裝置的計算才一致 |
| 卡片 id 用英文代號 | 陣列索引、隨機 id | 內容包增刪單字時舊進度不會錯位；每台裝置算出相同的 id |
| 單字與句型放進內容包 | 另開單字檔 | 延長計畫時只要換一個內容包檔案 |
| 卡片狀態另開一支同步 API | 塞進原本的 `/api/sync` | 不改已上線的協定；兩種資料的游標分開，互不影響 |
| 狀態欄位存成 JSON 文字 | 每個欄位一個資料庫欄位 | 伺服器不需要查詢裡面的欄位；之後加欄位不用改資料表 |
| 用網址 hash 換頁 | React Router | 只有兩頁，不值得多一個套件 |
| 正式網站用範例單字 | 把私人單字一起部署 | 部署出去的檔案都是公開的；私人內容要登入後才能取得，另開提案 |

**實作時遇到的事：**

- 原計畫的單字表有 4 個字在「新手村」和主題類別各出現一次，結構檢查擋下了重複的卡片代號；匯出指令稿改成保留第一次出現的字，並印出略過清單。
- ts-fsrs 不接受「比上次複習還早」的時間；裝置時鐘倒退時，改用上次複習時間計算。
- 同步原本放在今日任務頁裡，換到單字卡頁就會被卸載；改成在 App 層建立一次，兩頁共用。

## 面試可能被問的問題與回答方向

| 問題 | 回答方向 |
|---|---|
| 間隔重複怎麼排程？ | 用 FSRS：每張卡記穩定度與難度，評分後更新，算出下次到期日；每天只考到期的卡加上限內的新卡 |
| 為什麼要固定第三方演算法的版本？ | 演算法升級可能改變排程結果，兩台裝置版本不同就會算出不同的到期日；升級要另開提案並用測試確認 |
| 卡片 id 為什麼這樣設計？ | 要跨裝置一致、內容包改動時不錯位；所以由內容決定（英文代號），不用索引或隨機值 |
| 怎麼測「今天要考哪些卡」？ | 寫成純函式，輸入牌組、狀態與現在時間，用表格測到期、上限、本週類別、提前學習 |
| 兩種資料怎麼共用同步程式？ | 把「一種資料」抽象成路徑、讀寫函式與檢查規則，同一個迴圈跑兩次；打勾紀錄失敗就不同步卡片狀態 |
