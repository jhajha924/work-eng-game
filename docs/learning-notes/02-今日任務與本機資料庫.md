# 今日任務頁與本機資料庫

## 這段在做什麼（三句話以內）

把範本示範頁換成 App 的第一個真正畫面「今日任務」：打開就知道今天是計畫第幾天、本週主題、要做哪些任務。
每個任務可以打勾，紀錄存在瀏覽器內建的資料庫 IndexedDB，重新整理或關掉瀏覽器都還在。
經驗值和連勝天數不另外存，每次都由打勾紀錄重新算出來。

## 關鍵觀念

| 觀念 | 白話說明 | 在哪裡 |
|---|---|---|
| **IndexedDB** | 瀏覽器內建的資料庫，可以存大量結構化資料（比 localStorage 大很多），而且是非同步的，不會卡住畫面 | 瀏覽器提供 |
| **Dexie** | 包裝 IndexedDB 的套件。原生 API 要寫一堆事件回呼，Dexie 讓你用 `await db.taskLogs.put(...)` 這種寫法 | `src/progress/db.ts` |
| **資料庫版本** | `db.version(1).stores({ taskLogs: 'id, date' })`：第一個是主鍵，後面是索引。之後要加欄位就寫 `version(2)`，Dexie 會自動升級使用者手機裡的舊資料 | `db.ts` |
| **put 與 delete** | `put` 是「有就覆蓋、沒有就新增」，所以重複打勾不會變兩筆；取消打勾就 `delete` | `src/progress/progressRepo.ts` |
| **衍生資料** | 總經驗值、連勝是「從紀錄算出來的」，不是「存起來的」。只存事實（哪天完成什麼），結論每次重算，就不會不一致 | `src/progress/stats.ts` |
| **本機時區的今天** | `new Date().toISOString()` 是 UTC，台灣早上 8 點前會變成前一天；所以用 `getFullYear()`、`getMonth()`、`getDate()` 取裝置本機的年月日 | `src/progress/today.ts` |
| **自訂 hook** | `useTodayProgress` 把「讀資料庫、算統計、打勾」都包起來，`TodayPage` 只管顯示。畫面和邏輯分開，邏輯才好測試 | `src/app/useTodayProgress.ts` |
| **fake-indexeddb** | Node 沒有 IndexedDB，測試時用這個套件模擬，資料庫測試才能在 CI 上跑 | `progressRepo.test.ts` |

### 範例：連勝怎麼算

預設計畫的排程是 10/24～10/31 新手村、11/01 休息、11/02 開始正式期。

| 打卡日 | 今天 | 連勝 | 為什麼 |
|---|---|---|---|
| 10/29、10/30、10/31、11/02 | 11/02 | 4 | 11/01 不在排程裡，跳過，不算中斷 |
| 10/29、10/30 | 10/31 | 2 | 今天還沒打卡，先算到昨天，不會一早就歸零 |
| 10/29 | 10/31 | 0 | 昨天 10/30 沒打卡，已經中斷 |

程式的做法：只走排程裡的日子，打卡就 `run + 1`、沒打卡就歸零；`run` 每到 7 的倍數就加 50 經驗值。

## 為什麼這樣設計，放棄了什麼

| 決定 | 放棄的做法 | 理由 |
|---|---|---|
| 經驗值寫在內容包 | 程式裡寫死對照表 | 換內容包不用改程式 |
| 經驗值、連勝每次重算 | 另存累計值 | 取消打勾、之後跨裝置同步時，累計值很容易算錯 |
| 一張表 `taskLogs`，最低限度日也是一筆紀錄 | 另開一張表 | 計算時不用合併兩張表 |
| 這次就用 IndexedDB | 先用 localStorage | localStorage 容量小、只能存字串，之後還要搬家重寫 |
| 取消打勾直接刪除 | 軟刪除（標記刪除） | 目前沒有同步；做同步時再用資料庫版本 2 改成軟刪除 |
| 預設計畫先寫死在一個檔案 | 先做設定畫面 | 控制這次的範圍；之後設定畫面只要換掉 `defaultPlan.ts` |
| 第一次載入在 effect 的非同步回呼裡設定狀態 | 在 effect 裡直接呼叫會設定狀態的函式 | React 的 lint 規則 `set-state-in-effect` 會擋；另外用 `cancelled` 旗標避免元件卸載後還設定狀態 |

**刪掉的東西：** 範本的 `App.css` 和四張示範圖片（React、Vite、Cloudflare 標誌和主視覺），首頁已經不需要。

## 面試可能被問的問題與回答方向

| 問題 | 回答方向 |
|---|---|
| 為什麼用 IndexedDB 不用 localStorage？ | 容量大、可以存物件與建立索引、非同步不卡畫面；之後還要存錄音檔，localStorage 存不了 |
| 經驗值為什麼不直接存？ | 只存事實、結論重算，資料永遠一致；取消打勾或同步合併時不會算錯 |
| 時區問題怎麼處理？ | 「今天」用裝置本機時區；日期計算內部用 UTC，兩者分開；兩種時區都有測試 |
| 資料庫結構要改怎麼辦？ | Dexie 用版本號升級，舊資料自動遷移 |
| 前端邏輯怎麼測？ | 計算邏輯寫成純函式直接測；資料庫用 fake-indexeddb 在 Node 上測；畫面只負責顯示，用手動驗收與之後的端到端測試 |
| 使用者在無痕模式打不開資料庫怎麼辦？ | 顯示明確的錯誤訊息，任務照樣顯示，不會變成空白頁 |
