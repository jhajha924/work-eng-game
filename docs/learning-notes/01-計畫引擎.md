# 計畫引擎與內容包

## 這段在做什麼（三句話以內）

把「不含日期的學習內容」（內容包）和「使用者設定的日期區間」組合起來，算出每一週練什麼主題、每一天做什麼任務。
引擎是純函式：給一樣的內容包和設定，永遠算出一樣的排程，所以能用單元測試把規則一條條鎖住。
另外導入 Vitest，65 個測試跑在 GitHub Actions 的檢查流程裡，測試沒過就不會部署。

## 關鍵觀念

| 觀念 | 白話說明 | 在哪裡 |
|---|---|---|
| **純函式** | 只看輸入算出輸出，不改輸入、不讀系統時間、不連網路。好測試、好重用、出錯好重現 | `src/plan/buildSchedule.ts`、`allocateWeeks.ts` |
| **資料與規則分離** | 內容包只寫「第幾關第幾週練什麼」，日期全部由引擎算。延長計畫或換開始日都不用改內容 | `src/plan/types.ts` 的 `ContentPack` |
| **最大餘數法** | 把整數週數按比例分給各關：先發整數部分，剩下的依小數大小補 1。選舉分配席次也用這個方法 | `allocateWeeks.ts` 的 `largestRemainder` |
| **UTC 日期計算** | 日期一律用 `YYYY-MM-DD` 字串，內部轉成「UTC 午夜」計算。直接用本地時間會在某些時區差一天 | `src/plan/dates.ts` |
| **結構檢查** | 讀進來的 JSON 型別是 `unknown`，先檢查每個欄位再使用；而且一次回報所有錯誤，修內容包時不用改一個跑一次 | `src/plan/validatePack.ts` |
| **參數化測試** | `it.each([...])` 一張表產生多個測試，規格裡的 Example 表直接變成測試資料 | `*.test.ts` |
| **條件略過測試** | `it.skipIf` / `describe.skipIf`：私人內容包只在本機存在，CI 上自動略過 | `privatePack.test.ts` |

### 範例：39 週怎麼分給 6 關

範例包各關建議 4、5、4、4、5、4 週（共 26），權重 1、1、1、2、2、1（共 8）。多出 13 週：

| 關卡 | 權重 | 13×權重÷8 | 整數 | 小數 | 補 1？ | 最後 |
|---|---|---|---|---|---|---|
| Lv1 | 1 | 1.625 | 1 | .625 | ✅ | 4+2＝6 |
| Lv2 | 1 | 1.625 | 1 | .625 | ✅ | 5+2＝7 |
| Lv3 | 1 | 1.625 | 1 | .625 | ✅ | 4+2＝6 |
| Lv4 | 2 | 3.25 | 3 | .25 | | 4+3＝7 |
| Lv5 | 2 | 3.25 | 3 | .25 | | 5+3＝8 |
| Lv6 | 1 | 1.625 | 1 | .625 | ❌（名額用完） | 4+1＝5 |

整數部分合計 10，還剩 3 週。四個 .625 同分時，規則是「權重高的先、再來關卡順序在前的先」，所以 Lv1～Lv3 拿到，Lv6 沒有。

## 為什麼這樣設計，放棄了什麼

| 決定 | 放棄的做法 | 理由 |
|---|---|---|
| 內容包不含日期 | 日期寫死在內容裡 | 延長就得整份重做 |
| 開始日限定星期一 | 任何一天都能開始 | 每日任務照「這週第幾天」對應，原計畫也從星期一開始；之後畫面會自動對齊 |
| 用最大餘數法加權重 | 平均分配、每種長度手寫一張表 | 平均分配沒辦法讓技術表達多練；手寫表每加一種長度就要改 |
| 日期自己寫小工具 | 引入日期套件 | 只需要加減天數、星期幾、比大小，五個函式就夠，少一個依賴 |
| 公開範例包＋私人包只留本機 | 原內容直接公開 | 原內容有個人資訊；範例包結構相同，面試照樣能展示 |
| 個人禁用字詞放本機清單 | 寫在公開的測試檔 | 測試檔是公開的，寫進去等於公開那些字 |
| 關掉 Vitest 的檔案快取 | 保留快取加速 | 快取會記住舊的 `import.meta.glob` 結果，新增私人檔案後測試仍被略過；純函式測試不到 1 秒，不需要快取 |
| 測試檔另用 `tsconfig.test.json` | 測試和程式共用設定 | 測試要用 Node 的 `process`，正式程式不該拿到 Node 型別 |

**踩到的坑：** 一開始私人內容包已經產生，測試卻一直顯示「略過」。用暫時的測試印出 glob 結果，發現新檔案找得到、舊測試檔找不到，才知道是 Vitest 5 預設開啟的檔案快取（`fsModuleCache`）把舊的轉譯結果存起來了。

## 面試可能被問的問題與回答方向

| 問題 | 回答方向 |
|---|---|
| 計畫延長怎麼做到不改程式？ | 內容包和日期區間分離；排程是純函式，換設定重新算就好 |
| 為什麼要寫成純函式？ | 好測試（不用 mock 時間或資料庫）、結果可重現、前後端都能用 |
| 週數怎麼按比例分還保證是整數？ | 最大餘數法，同分時有明確的決勝規則，所以結果是確定的 |
| 時區問題怎麼處理？ | 介面只用日期字串，內部用 UTC 計算；測試在紐約與台北時區各跑一次確認結果相同 |
| 公開作品怎麼處理個人資料？ | 範例資料公開、個人資料留在本機並由 `.gitignore` 排除；測試也分公開與本機兩層 |
| 你的測試怎麼寫？ | 先寫規格與範例表，範例表直接變成參數化測試；CI 上測試失敗就不部署 |
