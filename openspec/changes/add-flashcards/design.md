## Context

計畫每天的任務裡有「新字 15 個進單字卡」與「複習單字卡」，原計畫的單字表有 9 類共 215 字（新手村 30 字、A～H 各 20～25 字）、句型有 9 個情境共 62 句；每週主題的 `vocabCategory` 欄位寫著本週要學的單字類別（例如「A 會議流程」、「A 會議流程（進階）」、「複習 A、B、F」）。這些內容含個人資訊，只能放在本機私人內容包；公開範例包要另外放通用的範例內容。

目前狀態：內容包沒有單字欄位；本機資料庫是 Dexie 版本 2（`taskLogs`、`meta`）；同步只處理打勾紀錄（`POST /api/sync`、D1 `task_logs`，以伺服器遞增的 `rev` 當游標，較新者為準）；前端沒有路由，只有今日任務頁。

限制：手機優先（寬度 360px）、離線可用（NFR-02）、零成本、TypeScript 嚴格模式、核心邏輯要有單元測試（NFR-07）、介面繁體中文（NFR-08）。

## Goals / Non-Goals

**Goals:**

- 內容包可以帶單字與句型，結構檢查涵蓋新欄位；私人內容包由匯出指令稿補上原計畫的 215 字與 62 句。
- 每天打開單字卡頁就知道要複習哪些卡：到期的複習卡加上最多 15 張新卡，新卡優先學本週主題的類別。
- 用 FSRS（ts-fsrs）排程，評分後立刻算出下次複習時間；離線也能複習。
- 卡片狀態在手機與電腦之間同步，規則和打勾紀錄一致。
- 排程、佇列、牌組產生都是純函式並有單元測試；伺服器 SQL 用 sqliteD1 測試。

**Non-Goals:**

- 自訂新增卡片（FR-07 的「可自訂新增」另開提案；牌組只來自內容包）。
- 語音合成、真人發音外連（第 1 刀順序 7「內容庫與語音合成」）。
- 單字卡相關的經驗值、徽章與動畫（第 1 刀順序 9；這次不自動打勾任何每日任務，使用者照舊自己打勾）。
- 複習紀錄的跨裝置同步（只存本機；之後做成長圖表時再加）。
- 卡片翻面的 3D 動畫與滑動評分手勢（第 1 刀順序 9）。
- 調整 FSRS 參數或依個人紀錄最佳化參數。
- 匯出／匯入備份（FR-16 另開提案）。
- 正式網站使用私人內容包（部署出去的檔案都是公開的；要登入後才從伺服器取得私人內容，另開提案）。正式網站這次用公開範例包的範例單字與句型。

## Decisions

### D1 內容包新增選填的 vocab 與 patterns

`ContentPack` 新增兩個選填欄位：`vocab: { category: string; words: { en: string; zh: string; example?: string }[] }[]`、`patterns: { scenario: string; items: { en: string; zh: string }[] }[]`。選填是為了讓沒有單字的內容包仍然有效，現有的排程與測試不受影響。`validatePack` 檢查：兩個欄位存在時必須是陣列；`category`、`scenario`、`en`、`zh` 是非空字串；`example` 存在時是字串；同一包內同一種類（單字或句型）的卡片代號（D2）不可重複，也不可是空字串。放棄的做法：另開一個單字檔案（內容包與單字會分開版本，延長計畫時要對兩個檔案）。

公開範例包新增 9 個單字類別（新手村單字，以及和範例包週主題 `vocabCategory` 相同的 A 會議流程、B 進度與排程、C 業務系統與製造、D 軟體開發、E 形容與語氣、F 數字日期、G 職涯對話、H 動作動詞），每類 10 個通用單字（共 90 個，各附一句例句），以及 3 個情境各 4 句的通用句型（共 12 句）；內容不得含個人資訊，並通過現有的禁用字詞測試。私人內容包由 `scripts/export_private_pack.py` 從原計畫的 `VOCAB`（類別 → 英文、中文、例句）與 `PATTERNS`（情境 → 英文、中文）轉出，空字串的例句不輸出。

### D2 卡片 id 由內容包 id、種類與英文代號組成

卡片 id 為 `<內容包 id>:<種類>:<代號>`，種類 `v` 是單字、`p` 是句型；代號把英文轉小寫，連續的非英數字元換成一個 `-`，再去掉頭尾的 `-`（例如 `follow up` → `follow-up`、`Shall we get started?` → `shall-we-get-started`）。同一張卡在每台裝置的 id 都相同，同步才對得上。放棄的做法：用陣列索引（內容包增刪單字後，舊的複習進度會對到別的字）、隨機 id（每台裝置不同）。

### D3 卡片正面中文、背面英文

主動回想的方向是「中文情境 → 說出英文」：正面顯示中文與類別（單字）或情境（句型），按「翻面」後顯示英文與例句（有例句才顯示）。

### D4 FSRS 用 ts-fsrs 5.4.2，關閉隨機擾動

`src/cards/fsrs.ts` 包一層 `reviewCard(cardId, state, rating, now)`：`cardId` 是卡片 id（新卡沒有狀態，靠它填入 id），`state` 為 null 時視為新卡（ts-fsrs 的 `createEmptyCard(now)`），回傳新的卡片狀態與一筆複習紀錄。參數用 ts-fsrs 預設值（目標記憶率 0.9），`enable_fuzz` 設為 false，讓相同輸入一定得到相同結果，測試與兩台裝置的計算才一致。版本固定 5.4.2：6.0.0 才發布不久且要求 Node 24 以上的執行環境，5.4.2 已穩定使用數個月。放棄的做法：自己實作 SM-2（規劃書已決定用 FSRS，記憶模型較準）。

### D5 每日佇列：到期複習卡在前，新卡在後，每天最多 15 張新卡

純函式 `buildQueue(deck, states, { now, today, weekCategory, newLimit })`：

1. 複習卡：有狀態且 `due` ≤ `now` 的卡，依 `due` 由早到晚。另外，狀態為學習中或重新學習中、且 `due` 在 `now` 之後 20 分鐘內的卡也列入（提前學習，避免「重來」後要乾等幾分鐘），排在其他複習卡之後。
2. 新卡：沒有狀態的卡。今天還能學的張數 = `newLimit`（15）減去 `introducedOn` 等於 `today` 的卡數，最少 0。先取類別等於本週類別的單字卡，再依內容包順序取其餘卡片（單字在前、句型在後）。

本週類別：今天所在週第一個週主題的 `vocabCategory`，去掉結尾的「（進階）」；新手村期間用內容包的第一個單字類別；找不到對應類別（例如「複習 A、B、F」）就沒有優先類別，直接依內容包順序。每評一張卡就用新的狀態重算佇列。放棄的做法：一次固定整天的佇列（「重來」的卡不會回來）。

### D6 本機資料庫版本 3 新增 cardStates 與 reviewLogs

Dexie 版本 3 新增 `cardStates`（主鍵卡片 id，索引 `due`、`dirty`）與 `reviewLogs`（主鍵 `<卡片 id>@<複習時間>`，索引 `cardId`、`reviewedAt`），`taskLogs`、`meta` 不變，升級不需要搬資料。評分時在同一個交易內寫入新的卡片狀態（`dirty` 1、`updatedAt` 依 `nextUpdatedAt` 規則）與一筆複習紀錄。卡片狀態只會更新，不會刪除，所以不需要墓碑。

### D7 卡片狀態用獨立的同步 API 與游標

新增 D1 資料表 `card_states`（遷移檔 0002，欄位：`id` 主鍵、`state` JSON 文字、`updated_at`、`rev`，`rev` 建索引），以及 `POST /api/sync/cards`：請求 `{ since, changes }`、回應 `{ cursor, changes, hasMore }`，規則和 `/api/sync` 相同（需要登入；整批檢查，任何一筆不合法就回 400 且不寫入；只有嚴格較新才覆寫並給新的 `rev`；`since` 大於最大 `rev` 時視為 0；每頁 500 筆）。前端游標存在 `meta` 的 `cardSyncCursor`，和打勾紀錄的 `syncCursor` 分開。`syncOnce()` 先同步打勾紀錄、成功後再同步卡片狀態；任一階段失敗就以那個結果結束，`received` 合併兩個階段。本機合併沿用 `mergeRemote` 的規則（改成對任何有 `updatedAt` 與 `dirty` 的紀錄通用）。放棄的做法：把卡片狀態塞進 `/api/sync` 的同一個請求（要改動已上線的協定與規格，兩種資料的 `rev` 也會混在一起）；把 FSRS 欄位拆成多個資料庫欄位（伺服器不需要查詢這些欄位，JSON 文字較簡單，欄位增加時也不用改資料表）。

### D8 前端用網址 hash 切換頁面

`useHashRoute()` 讀 `location.hash` 並監聽 `hashchange`：`#/cards` 顯示單字卡頁，其他值顯示今日任務頁。今日任務頁的「今天的任務」區塊加一個連結「複習單字卡（今天 N 張）」，N 是佇列長度；單字卡頁上方有「回今日任務」。放棄的做法：加入 React Router（只有兩頁，多一個套件不划算；之後頁面變多再換）。

## Implementation Contract

**行為：**

- 打開 `#/cards`：上方顯示「回今日任務」與「今天還有 N 張」；佇列有卡時顯示第一張的正面（中文、類別或情境）與「翻面」按鈕；翻面後顯示英文、例句與「重來」「困難」「良好」「簡單」四個按鈕；按下評分後立刻顯示下一張；佇列清空時顯示「今天的單字卡已完成！」。內容包沒有任何卡片時顯示「這個內容包沒有單字卡」。
- 評分後重新整理頁面，剛評過的卡（除非已再次到期）不會再出現；今天已學的新卡數會計入每日上限。
- 本機資料庫打不開時，單字卡頁顯示「無法存取本機資料庫，單字卡進度無法儲存」，不顯示卡片。
- 已登入時，評分後依現有的同步時機（30 秒、切到背景、恢復連線、開頁）同步卡片狀態；另一台裝置同步後，同一張卡的下次複習時間相同。

**資料格式：**

- 卡片：`{ id: string; kind: 'word' | 'pattern'; en: string; zh: string; example?: string; group: string }`，`group` 是單字的類別或句型的情境。
- 卡片狀態（本機與同步相同，另加本機欄位 `dirty`）：`{ id, due, stability, difficulty, elapsedDays, scheduledDays, learningSteps, reps, lapses, state, lastReview, introducedOn, updatedAt }`。`due`、`lastReview`、`updatedAt` 為 ISO 時間字串（`lastReview` 可為 null），`introducedOn` 為 `YYYY-MM-DD`，`state` 為 0～3 的整數（新、學習中、複習、重新學習），其餘為大於等於 0 的數字（`reps`、`lapses`、`learningSteps` 為整數）。
- 複習紀錄：`{ id, cardId, rating, reviewedAt, state, due }`，`rating` 為 1～4（重來、困難、良好、簡單）。
- 伺服器檢查卡片 id：`<內容包 id>:<v 或 p>:<代號>`，內容包 id 與代號只含小寫英數與 `-`。

**失敗模式：** 同步失敗沿用現有的四種結果與狀態列文字；卡片狀態格式不合伺服器規則的不送出，留在本機（和打勾紀錄相同）。

**驗收：** `npm test`（deck、fsrs、queue、cardRepo、validatePack、worker cards 的 validate 與 repo、兩台裝置同步卡片狀態的測試）、`npm run lint`、`npm run build` 通過；本機與正式網站手動驗收（任務 [M]）。

**範圍：** 只包含上列內容；Non-Goals 列出的項目都不做。

## Risks / Trade-offs

- [英文相同的兩張卡代號相同] → `validatePack` 把重複代號當錯誤回報。原計畫有 4 個新手村單字在主題類別再出現一次，匯出指令稿略過重複的字（保留第一次出現的，並印出略過的字），私人包因此是 211 個單字。
- [內容包修改單字的英文，舊進度對不上] → 視為新卡重新學；舊狀態留在資料庫，不影響其他卡。
- [兩台裝置同時離線複習同一張卡] → 以較新的 `updatedAt` 為準，較舊那次的排程結果會被覆蓋（複習紀錄仍留在各自本機）；單一使用者很少同時發生，可接受。
- [正式網站只能用範例單字，不是原計畫的 215 字] → 這次先讓單字卡流程上線；私人內容的載入方式另開提案（例如登入後由 Worker 從 D1 回傳）；私人內容包目前只用於本機測試（確認原計畫的 215 字與 62 句通過結構檢查、卡片代號不重複）。
- [ts-fsrs 版本更新改變計算結果] → 版本固定，升級另開提案並以測試確認。
- [卡片狀態 JSON 未來加欄位] → 伺服器只檢查必要欄位並原樣保存，前端讀取時補預設值。

## Migration Plan

1. 本機：`npx wrangler d1 migrations apply work-eng-game --local` 套用 0002。
2. 正式：先 `npx wrangler d1 migrations apply work-eng-game --remote`，再 commit、push 觸發部署（舊版前端不會呼叫新 API，先建資料表不影響現有功能）。
3. 回復：新 API 與資料表只被新前端使用；回復時重新部署前一版即可，`card_states` 資料表留著不影響。
4. 私人內容包：使用者重新執行匯出指令稿，產生含單字與句型的私人內容包（不進版本庫）。
